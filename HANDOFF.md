## 3. How the site is built

- The boards in `tools/canvas/` are the design source.
- `tools/build.py` compiles the boards into plain HTML (template as JSON + logic class). `tools/wire.py` applies site-only changes (Discord login label, saved decks, server-side codes, live standings).
- `dc-lite.js` is the small page engine; `league.js` is sign-in, deck saving, scoring and standings (plain `fetch` to Supabase, no SDK).
- `data.js` holds `PCMT_MATCHES` / `PCMT_RESULTS`. It is **live data** kept up to date by the scheduled check. Never overwrite it from a build.
- `data.js` and `players.js` must stay strict JSON inside each `var X = [...]` (double quotes, no trailing commas, no comments inside the arrays). Supabase reads both from the live site every hour to pay VP.

## 4. Making a change (the routine)

1. Edit the board(s) in `tools/canvas/*.dc.html`.
2. Build: `python3 -I tools/build.py tools/canvas assets <out>`
3. Test: copy the repo `data.js` and `pickems.js` into `<out>`, serve it (`python3 -m http.server 8766 --directory <out>`, in the background) and run `NODE_PATH=$(npm root -g) node tools/smoke-test.js http://localhost:8766 <out>/shots`. It mocks Supabase and checks every page on desktop and phone. Look at the screenshots for visual changes.
4. Copy `home.html index.html customization.html leaderboard.html guide.html login.html store.html library.html pickems.html players.js league.js dc-lite.js variant-art.js _headers` from `<out>` into the repo root (**not** `data.js`, `pickems.js` or `rankings.js`, **not** `assets/`, **not** `mvp-vs.html` or `admin.html`, which are hand-written). Copy changed boards into `tools/canvas/`.
5. Update the design canvas with the changed boards so it stays in step with `tools/canvas/`.
6. Commit, then `git fetch && git stash && git rebase origin/main && git stash pop && git push` (the scheduled check also pushes to `main`).

`league.js` and `dc-lite.js` sources live in `tools/`; edit those, not the root copies.

## 5. Game rules (as built)

- Deck: 11 players, roles filled, budget 100, max 2 per team, twin rule; one IGL scores ×1.5.
- Scoring per series (from the Oct 19 2026 gameweek): kill +1, every 5 kills on one map +1, assist +0.5, first blood +0.5, Toxic rating (PCMT.gg's RT column, `R1.0` in its data) #1/#2/#3 in the series +3/+2/+1, top ACS +2, top KAST +1 (ties all get it), every 50 ADR +1, map win +1, map won by 4-9 +1 / by 10-12 +2 / 13-0 +7 (instead of the round-difference points), map lost 0-13 -5, 0 kills on a map -5, series won 2-0 +2 / 3-0 +3 / 3-1 +1 (2-1 and 3-2 get nothing extra), 4K +1, 5K (ace) +3. Deaths don't score. The same rules live in three places that must agree: `seriesPoints()` in tools/league.js (with `SCORING`), `pcmtSeriesPoints()` in the Main board, and `vp_series_points()` in setup/vp-setup.sql. Credits are the week's card numbers (cards below zero count 0), rounded to a whole number.
- **Subs (from Nov 1 2026):** when a player sits out and someone not listed on that team plays in their place, staff enter it on backend.html, **Subs** tab: "Sub (who played)" and "Player they replaced", both search boxes that fill in as you type (the sub list shows names seen playing as subs since Nov 1 with the series, then every site player; any other name can be typed as written on PCMT.gg; the player list puts players who sat out the sub's series first). Before saving it shows which series it will count in. Each sub belongs to one gameweek (`week` = its start, as vp_week_start gives it), filled in by the tab: the latest week not yet paid where the sub already played in place of that player, else the week whose games are next (this week until decks reopen, then next week). It only counts in that gameweek's series, so nothing carries into later games; the tab shows it as active until decks reopen, it can be removed until the week ends, and once the week's points are paid it's locked under Past gameweeks (the database refuses adding or removing subs in a paid week). Paid subs are kept, not deleted: the Leaderboard adds up every week from the results each time it loads, so deleting one would take that week's points back off. Saved in Supabase `player_subs` (sub = PCMT.gg name in lower case, player = players.js id, week; everyone reads, staff and site admins add and remove; `setup/subs-setup.sql`, also in vp-setup.sql). A sub counts in each series of its gameweek where "~<sub>" played (in data.js, someone not listed on that team), the player didn't, and the player's team is in the series. It's applied to the results as they load, not in data.js (data.js stays exactly as PCMT.gg has it): `applySubs()` in tools/league.js (every page; The Deck board and the Leaderboard read the same result objects) and `vp_apply_subs()` in `vp_ingest` for the VP payout; both move the sub's stats and per-map kills to the player and set `r.subs = { <player>: <sub> }`, so seriesPoints, pcmtSeriesPoints and vp_series_points are unchanged. First entry: nana for Dovie (SEAL, NOOT vs SEAL, Nov 1). A listed bench player coming in for a teammate isn't a sub here (they score their own points; the tab says so). The Guide explains it under the scoring table. 4Ks/5Ks for a sub go under the player they replaced (the 4Ks & 5Ks tab lists them once the sub is saved). Test: `node tools/subs-test.js "psql -h /tmp/pg -p 5499 -U postgres" players.js` (who can add and remove, paid weeks locked, site and database agree on every data.js result and on the points, cases that must not count including other gameweeks).
- 4Ks and 5Ks are the only numbers typed in by hand (PCMT.gg doesn't have them). Staff enter them on backend.html into the `multikills` table, keyed by series `start|a|b` as in data.js. league.js attaches them to each result as `multi: { id: [4K, 5K] }`. Everything else comes from PCMT.gg's JSON API (`/api/matches.json` lists events, `/api/matches/<event>.json` their matches, `/api/matches/<event>/<match id>.json` one match with full stats; helpers in tools/pcmt-api.js). `node tools/pcmt-sync.js` (`--dry` to preview) adds new matches and finished results to data.js, drops schedule entries older than 14 days, and fills in Pick'ems series times, links and scores; it never adds anything before the Oct 19 2026 gameweek. `node tools/pcmt-result.js <event> <match id>` (or a match page url) prints one PCMT_RESULTS entry (series stats [K, D, A, FK, ACS, KAST, ADR, RT] plus `maps: [{ map, a, b, k: { id: kills } }]`). The scheduled sync runs pcmt-sync.js.

Before that they ran Monday to Monday; the short week Mon Oct 26 - Thu Oct 29 bridges the two (keys: weekStart in tools/league.js, pcmtMondayStart in the Main board, pcmtWeekKey on the Leaderboard, wkStart on Home, vp_week_start in SQL). **Deck lock, once per gameweek:** Thursday 09:00 UTC, unless the week's first game (NA or EMEA) is on Saturday or later (New York day), then 6 h before it. ## 10. VP (Credits) and the Store paychecks panel

- VP for a gameweek = the sum of the card numbers of the deck that counted that week (the same deck the leaderboard scores: locked deck, transfer and fallback rules). Each card counts at least 0, and there is no IGL bonus.
- Paid when the gameweek ends (Monday 09:00 UTC), when the card numbers reset. If a late result raises a card, the difference is paid as a top-up. A payout is never taken back.
- Server side: `setup/vp-setup.sql`. `vp_sync()` runs every hour (pg_cron, minute 7). It fetches the live `data.js` and `players.js`, recomputes every finished gameweek with `vp_compute` and writes only the missing amounts to `vp_ledger`. Players can only read their own rows and cannot run the payout. `vp_sync_log` keeps the last runs.
- Ledger lines: `week` = payout (positive), `pack` = VP spent on a card pack (negative, `detail.pack` = pack name). A check constraint enforces this. The Bank is the sum of a player's lines, so buying a pack lowers it.
- Site side: `league.js` reads `vp_ledger` and shows it in the "Paychecks and spending" panel at the bottom of store.html (top line: total Credits). Last Paycheck is what the ledger paid for the last finished gameweek.
- Test: start a throwaway Postgres, then run `node tools/vp-test.js "psql -h /tmp/pg -p 5499 -U postgres" <out>/players.js`. It checks the SQL against the site's own scoring in random seasons, plus top-ups, re-runs and permissions.
- Next phases: card packs bought with VP, cards stored per player on the server, a card album page, then MVP VS hands from owned cards and VP bets (game run on the server).

## 11. Cards and card packs

- Catalog: every store player is a Common card (`c:<player id>`); variants are `v:<variant id>` with a rarity (The Role of Yoru, Straight Ace, claps Clove and Croc Spotlight = Rare). Each card has a region (from its team).
- Packs: NA Card Pack and EMEA Card Pack, 5 cards each, drawn only from that region's current-season cards. Odds per card (Nov 5 2026, every pack): Common 85, Rare 10, Legendary 5 (Epic 0). A roll for a rarity the pack has no released cards of gives a Common (it used to drop to the tier below, which would have turned Legendary rolls into extra Rares); so a pack with no Legendary is 90 / 10, and the Store's odds line shows what a pack can really drop (`pcmtPackOdds`).
- Throwback packs: NA S1, NA S2 and EMEA S1 Throwback Pack, same size and odds, each drawing only that season (`season` on `cards` and `card_packs`; null = current). Every player of the season is a Common `o:<MVP VS card id>` (e.g. `o:nas1-igneous`); that season's champions also have a Rare `v:champ-<MVP VS card id>` with the trophy art (6 S1 NA, 5 S2 NA, 5 S1 EMEA). Cards show that season's team, logo and MVP VS stats (`pcmtPastCard` in the Store and Library boards). They are for MVP VS and the Library, never The Deck. Past-season variants go in `PAST_VARIANTS` in tools/cards.py and only drop from that season's pack. Clove Value (lore) and Butterfly Effect (claps S2) were taken out of packs on 2026-10-21; copies already pulled stay.
- `tools/cards.py` holds the variants, packs and odds and writes `setup/cards-setup.sql` (run `python3 -I tools/cards.py <out>/players.js`). Re-run it and the SQL when players or variants change; removed cards are switched off, never deleted.
- Buying is only the `buy_pack(pack)` function on the server: it checks the price, the buyer's VP (one purchase at a time per player), writes the `pack` line in `vp_ledger`, draws the cards, adds them to `user_cards` (duplicates are counted) and logs `pack_openings`. The browser only shows the result.
- Prices and "Open to everyone" are set on backend.html (Card packs tab). Until a pack is open to everyone, only admins and PCMT Team staff can buy it (a price of 0 is free, for testing).
- The Store board carries a copy of the Customization board's pack opening (`pcmtPackAnim`), changed for store packs: a team per card, rarity glow and tag, variant art, NEW / ×n badges, and it stays open until closed. The pack images on the Store are that same pack, drawn once (assets `1ebfc850…` NA, `87166e6b…` EMEA).
- Champion cards: a player only has a champion card (Rare, trophy art, gold sheen) and the trophy by their name for the season they won: S1 NA (YD), S2 NA (JDG) and S1 EMEA (WFC), in those throwback packs. Nobody has won NA S3 or EMEA S2 yet, so current-season cards have no champion card. Current-season cards of past champions (`PCMT_SITE_CHAMPS`) still show the small trophy by their name, on The Deck, in packs, the Library and MVP VS; a past-season card shows it only if the player won that season. The 11 old current-season champion cards were switched off on 2026-10-21 (copies already pulled stay). ## 23. LosersQ (losersq.html, added Oct 31 2026, backend-only)
- Team simulator: pick 5 players from the NA S3 pool (every NA S3 card in trumps-cards.js, subs included) and a coach, choose which real team's spot you take, and the bot plays a whole simulated NA Season 3. No budget yet.
- Files: `losersq.html` (hand-written page, same header and footer as the site), `losersq.js` (the sim engine `PCMT_LOSERSQ` and the page), `losersq-roles.js` (built by `node tools/losersq-roles.js`), `media/losersq-intro.mp4` (3 s intro, plays once per browser session, Skip / Esc, skipped with reduced motion), `losersq/test.js`, `setup/losersq-setup.sql`.
- Access: `site_pages` row `losersq` (not launched, added Oct 31 2026). Staff and site admins open it from backend.html (Pages tab → Open); everyone else is sent to Home. It's in `LAUNCH_PAGES` (tools/league.js) and the gate lists in mvp-vs.html and losersq.html. It has no menu link or Home tile: add those before pressing Launch.
- Format: NA S3's. Groups Alpha (C9, T1, FSG, TL, SSG, RRQ, IHOP, FNC) and Omega (SRB, SPG, TS, NAVI, BAKA, 100T, EPY, DFM), Bo3 round robin over 7 weeks (ties: series, map diff, head to head, round diff), top 4 of each into the S3 double elimination bracket (copied from pickems.js na-s3; lower final and grand final Bo5). Map pool: Lotus, Ascent, Haven, Split, Summit, Sunset, Pearl.
- Ratings: LQ rating = 0.6 x Toxic rating + 0.25 x ACS/240 + 0.15 x KAST/72, pulled toward 0.93 over 6 maps (so small samples don't dominate); shown x100. Team rating = average of the 5, minus role gaps (no controller -3.5, no initiator -2, no sentinel -1.5, no duelist -1, each duelist past 2 -1.5), plus 0.45 per pair of players from the same S3 team. Drafted players leave their real team, which fills in with its 6th player, then the best free sub, then a stand-in (84).
- The bot: veto (ban, ban, pick, pick, then bans or Bo5 picks, decider), each team has a comfort per map and a form for the season, a form per map and win-streak momentum; every round is a coin flip weighted by logistic(1.8 x strength difference). Kills, deaths and assists per map come from the rounds played, split by player rating, DPR and role. Tuning constants are at the top of losersq.js.
- Roles (Oct 31 2026): each player on your team can be moved to any role they played in NA S3, and only those (the role buttons under each player; unplayed roles are greyed out and the engine refuses them too). `tools/losersq-roles.js` reads every NA S3 map from PCMT.gg's API (`/api/matches/s3-na.json`, agent per player per map, agent → role as in trumps/build_cards.py) and writes each player's maps, Toxic rating, ACS, KAST, DPR and agents per role to `losersq-roles.js` (`PCMT_LQ_ROLES`, keyed by MVP VS card id). A player's rating on a role = the LQ formula on that role's numbers, pulled toward their overall LQ rating as if over 5 maps (`ROLE_PRIOR`), so one great map on a new role can't make a star; ACS, KAST and DPR on that role feed the box scores. Their listed role (The Deck / MVP VS) is the default and always allowed. Every team, bot teams too, plays its players on their listed role with that role's numbers. NA S3 is finished, so the file isn't in the hourly sync; re-run the tool if PCMT.gg corrects a match. It stops if a new agent has no role (add it to ROLES there and in build_cards.py).
- The pool's role filter lists everyone who has played that role, showing their numbers on it; small dim icons show each player's other roles.
- Coaches: Tactician (smart veto, a bit better on maps), Hype Man (double momentum, bounce back after a lost map), Analyst (edge vs higher-rated teams), Vet (playoff and overtime boost), Bestie (full-team chemistry for mixed rosters, steadier form).
- With the real rosters the bot gives SPG ~42% for the title, C9 ~12%, then the pack (run `node losersq/test.js` to see the table; it also checks the format, the box scores and that a season code replays the same season).
- The draft (players, roles, coach, spot, name) is kept per browser in localStorage `pcmt-losersq`. Nothing is saved to Supabase yet.
- Ideas for later: a budget using players.js prices, past-season player pools (nas1, nas2, emeas1 are already in trumps-cards.js), saving runs and a LosersQ leaderboard.

## 25. Database (database.html, added Nov 10 2026, staff only)

- One panel, "PCMT NA" (with the NA logo): new rank, name, team, roles, peak, tracker score, in one table that scrolls with the page (header row sticks). Search (name, team, roles), filter by peak or role, sort by any column. "Last updated" at the bottom is the newest `updated_at` in the table.
- Rows 1-80 are the staff sheet. Rows 81-116 (Nov 10 2026) are the NA players on PCMT.gg's stats page (any NA season) who weren't on the sheet: no rank, peak or tracker yet, so they show NA and sit at the bottom when sorting by rank. The table still keeps the sheet's rank delta, maps and games, which the page doesn't show.
- Role (Nov 10 2026): one per player, Duelist, Initiator, Controller or Sentinel: their most played role on PCMT.gg (maps per agent on their player page, all seasons; a tie goes to the role with more rounds). Players with two PCMT.gg pages are added together (rudra + rudesubs, nameless + TheNam3Less1, sylos + beans). Players with no agent data on PCMT.gg got the first role listed on the sheet, or NA if the sheet had none of the four (Flex, Clove and so on).
- Team is `NA` for everyone until teams come in; set `team` per player in Supabase. Peak `NA` means no rank (it was Radiant on the sheet, with no tracker score); it sorts below Iron.
- The rows live only in Supabase, table `player_database` (setup/database-setup.sql makes the table and its `site_pages` row; the rows themselves aren't in the repo). It also keeps `discord`, `riot` and `mark` (the sheet's gold/red rows), which the page doesn't show. Only site admins and PCMT Team staff can read or change them (RLS), so the page is staff-only even if it's launched. When you edit rows in Supabase, also set `updated_at` to now() so the date moves.
- Access: `site_pages` row `database`, opened from backend.html (Pages tab → Open). It's in `LAUNCH_PAGES` (tools/league.js) and the copies of that list in mvp-vs.html and losersq.html.

## 26. Patch notes (backend.html, Patch notes tab, added Nov 10 2026)

- Staff write a title and a note; the date fills in with today's date (New York). Go live (press twice) saves it to `patch_notes` with live = true, and the newest live note (by live_at) becomes the Latest Patch Notes panel on Home for everyone, one paragraph per blank line in the note.
- The list under the form shows every note: ON HOME (the one Home shows), LIVE, or TAKEN DOWN. Take down / Go live again / Delete (press twice). Taking down the one on Home shows the next newest live note; with none live, Home shows the note written into the Home board (`PCMT_HOME_NOTE`).
- setup/patch-notes-setup.sql makes the table (already run on the live project). league.js loads the newest live note on Home only (`window.PCMT_PATCH_NOTE`).
- Home (Nov 10 2026): the patch note sits where the NA champions panel was (top of Home, under the hero), with no "Latest Patch Notes" heading. The hard-coded SPG champions panel is gone from the Home board.
- Champions tab (backend.html): builds a champions panel and posts it as a patch note (`patch_notes.champ` = { kicker, name, team, logo, color, mapsLabel, maps: [{ map, w, l }], statsLabel, stats: [{ player, kda, acs, rating }] }). Team picks fill the name, logo and colour (CH_TEAMS in backend.html, copied from the Home board's team lists; a new season's teams need adding there, or use Other); Fill players puts in the team's newest PCMT.gg roster (rosters.js). The live preview uses the Home panel's .hm-cb styles (copied into backend.html). Home draws it inside the patch note with the trophy, the best rating in gold, and the note text under it. Under the form, Posted champions panels lists them with Take down / Go live again / Delete (the same buttons as the Patch notes list).
- Current version (Nov 11 2026): the box at the top of the Patch notes tab saves `site_settings` key `version` (setup/site-settings-setup.sql). version.js puts "Version <it>" into every footer span with `data-pcmt-version` (all boards, mvp-vs.html, losersq.html, database.html); league.js loads version.js on the built pages. The last version seen is kept in localStorage `pcmt-version` so it shows straight away. The "Version 1.3" written in the boards is only what shows before that loads.
